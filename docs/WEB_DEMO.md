# 本地网页演示

项目定位为**深度学习课程大作业**，题目为“基于人体骨架时序建模的行人过街意图预测”。

网页为同屏计算工作台：左侧固定视频、骨架、行人 ID 与所选记录，右侧用可旋转的三维空间展开 YOLO26 Pose、ByteTrack、LSTM、ST-GCN 到分类输出的完整流程，分析期间直接接收实际前向计算的采样输出。上方选择视频、开始分析，完成后保存结果。

## 首次准备

先按照仓库说明准备 Python 3.9、基础依赖、PyTorch 和现代 YOLO 环境。再安装网页依赖并构建前端：

```sh
python -m pip install -r requirements-web.txt
python download_final_models.py
cd web_demo
npm install
npm run build
cd ..
```

本机还需能执行 `ffmpeg`；它负责将结果转为浏览器可播放的 H.264 MP4。模型默认取自 `weights/final/`，服务启动时按发布清单校验全部文件。网页无需远程 API、账号或字体 CDN。

## 启动与操作

```sh
python run_web_demo.py
```

打开 **http://127.0.0.1:8765**。本仓库已配置的 Mac 环境也可直接运行 `.venv/bin/python run_web_demo.py`。

1. 拖入或选择 MP4、MOV、AVI 视频，等待读取文件信息和兼容预览。
2. 点击“开始分析”，默认进入“三维网络 / 实时推理”，首先显示原有可旋转的三维网络。当前只执行一个推理任务；网络层输出随计算送入页面，无需等视频分析完成。
3. 选择行人，浏览八个阶段：全流程、视觉编码、跟踪与输入、门控记忆、未来骨架、空间图卷积、时间卷积、意图输出。左键拖动旋转、滚轮缩放、右键平移，点击单元检查实际值和采样坐标；可聚焦单元或重置视角。
4. “慢放本次计算”固定一个真实算式，后台继续推理；“跟随最新结果”立即显示最新算式。支持单步、倒拖、速度和连续讲解。真实数值直接标在原有网络层、关节、门控、特征单元与分类柱旁，贡献沿这些原对象之间的连接传递。“自动跟随当前步骤”默认开启，自动靠近当前算式及其输出；拖动、缩放或平移会暂停镜头跟随，“恢复自动跟随”可继续。“重置视角”返回当前章节全景。“展开参与项表”只展开数值表，不新增另一张演算图。“专注演示”扩大画布。分析后切到“记录讲解”，可选择历史记录；切换“数值推导”可使用原 150 秒讲解时间轴，检查详细乘加、门控和卷积。选择记录帧会定位视频，视频拖动使用最近保存记录。
5. 分析完成后点击“保存结果”，下载标注 MP4、逐帧 JSONL 或完整 ZIP。

“停止分析”会在当前模型调用后的帧边界停止任务。页面关闭不会自动取消分析；重新打开页面会恢复最近任务或当前运行任务。需要重新分析时，重新选择视频创建新任务。

## 实时三维计算

实时展示通过生产推理的前向钩子采样，**不为动画额外执行一次模型**。YOLO 采集融合后模块输出；LSTM 采集五轮预测中的十层 h/c 状态、序列输出与未来骨架；ST-GCN 采集十块空间/时间/残差输出，以及池化、Logits 和本次分类分数。行为网络只在积累 50 次有效观测后出现实测输出。

Three.js 使用实例化单元显示特征体、时间骨架、图邻居和分类柱。光迹由收到的层事件触发，延长至可观察的时间；它不是 GPU 内部执行时间动画。骨架仍为图像 x/y，第三量为置信度，三维纵深表示时间或特征布局。实时未采样的权重、门值和中间项显示为空结构，详细计算见“记录讲解”。

- 每秒最多采集 4 个推理帧，每帧最多 3 人；浏览器最多每秒刷新 10 次数据。模型处理吞吐、采样率与屏幕渲染帧率相互独立。
- 每事件上限 64 KiB，每帧最多 128 事件 / 768 KiB；重连缓冲最多 512 事件 / 4 MiB。只传真实采样切片与原尺寸、索引，不复制全层张量。
- `GET /api/jobs/<id>/live` 为 SSE：支持序号、重连、缺口快照、终态。任务结束后保存 `live.json`，重开页面可检查最后采样帧；它不是完整逐帧计算录像，也不含在结果 ZIP 中。
- 页面区分采集帧、已收到层数、当前帧耗时和接收状态。层耗时为主机墙钟区间，包含嵌套观察开销，不是 GPU 核函数耗时。预览显示最近完成的画面，可能稍落后于正在计算的帧。
- 无 WebGL 或渲染上下文丢失时，可恢复三维画布或转入数值视图；减少动画设置会关闭流动光点。

## 三维网络中的逐项数据流演算

默认主场景直接在原有特征体、分层网络和时间骨架上标出当前输入、权重、乘积、累加和输出，不另设演算方块。原生索引匹配时高亮具体单元；原图未展开该索引时，在所属层边界标出来源及“层级标注”，不会借用另一个神经元。图卷积在原骨架上标出实际邻居与连接，类别计算沿原池化特征、权重矩阵、Logits 和分类柱展示。沿贡献连线移动的标签携带当前项的实际数值，与下方进度和参与项表使用同一游标；暂停或倒拖可重建相同状态。前 3 项慢放，后续项加速累计，所有项都完整参与求和，不因分页省略。

- **当前项 / 已累计 / 待累计**描述讲解进度，不冒充硬件执行时钟。
- **无连接**指对当前选定目标的原始图邻接为零；有连接但学习系数或输入为零，单独标作**贡献为零**。卷积越界输入明确标为**零填充**。
- **未采集**表示缺少数值，不能推断模型未使用该单元。没有完整观测的行为阶段保留等待状态。
- 三维图保留原有采样结构，表格每页 8 项；顶部同时给出完整项数和连接计数。可按无连接、零贡献或未采集筛选，也可点选原图中与参与项索引匹配的单元，跳到这一项。
- “慢放”保留当前算式的帧与 ID，旁边显示最新采集帧；实时接收的新帧不会替换正在讲解的数字或其三维张量；LSTM 的三维状态也跟随所选算式的预测轮次。旧任务没有算式遥测时默认使用记录重算。

实时完整算式覆盖：首层 YOLO 中心 RGB 3×3 卷积与实际 SiLU 输出、归一化、首轮 LSTM 256 维解码、五轮坐标还原、第一 ST-GCN 块的全部 51 个空间候选项及 576 个时间卷积项、221 项全局池化、当前预测类别的完整 256 维分类和三个类别的 Softmax。最多三个行人分别记录，未增加模型前向次数。此处追踪的是明确标注的代表性输出，不是保存网络的每个标量。

记录讲解进一步提供四个 LSTM 门的全部 51+256 项、记忆更新、全部五轮解码及十个 ST-GCN 块。LSTM 门值由实际权重重建，未直接逐门采集，因此不显示为独立实测输出；独立采集的 h/c 状态和其他算子结果用于核对。

## 原三维图中的邻域消息

空间图卷积章节借鉴 [Distill 的 GNN 交互讲解](https://distill.pub/2021/gnn-intro/)：选中接收节点、沿连接读消息，再检查聚合结果。它沿用项目实际的 ST-GCN 运算，保持原来的透视骨架和特征体，未增加独立演算图。

- 点击原骨架关节，或使用“接收关节”选择器，查看这个关节的实际输入邻域。节点卡显示投影特征乘以有效邻接系数 `A × edge_importance`；有向路径抵达原输出单元。绿色 / 珊瑚色与明确的正负号编码贡献方向，短条按当前邻域最大绝对贡献统一缩放，不表示概率。
- “读取邻域 → 沿边传递 → 求和写回”可定位讲解阶段。“顺序传递”逐项播放；每条有效连接（包括零贡献）停留约 1.6 秒，无连接候选快速检查，51 个候选项仍完整计入。源卡上的勾号与目标卡小计表示讲解进度。
- 输出卡展示三个分区的当前小计、独立采集的输出与重建误差。该输出位于 BN / 时间卷积之前。镜头自动聚焦邻域，写回时靠近结果；手动拖动暂停跟随。手机仅展开当前消息，原三维场景和完整求和保留。
- 新实时记录保存第一块、通道 0、中间时刻的 17 个实际关节输出，以及 49 条原始拓扑连接的有效系数，所有行人分开保存；切换接收关节不增加模型前向次数。记录讲解使用各块已经采集的对应输出切片。旧实时记录缺少完整切片时锁定原接收关节，不补造数据。骨架形状用作关节拓扑定位，卡片中的投影特征不冒充图像坐标。

## 记录讲解与详细数值

YOLO 从所选源视频帧重算；LSTM / ST-GCN 使用保存至三位小数的 50 次观测和本地权重重算。左侧明确显示视频原分析分数，右侧为当前记录的重算结果，两者可能不同。没有有效历史时只展示结构，不填造激活值。

- **YOLO26**：23 个 Backbone / Neck 模块与 9 个输出分支的实际采样特征图；第一层三个真实位置的 RGB 3×3 卷积、完整 27 项乘加、BatchNorm 和 SiLU 数值。推理分支与生产配置一致，当前默认使用 NMS；重算保留未融合 BN，以供检查。
- **跟踪与张量**：保存的 ByteTrack ID、真实历史骨架、50×17×3 到 50×51 的标准化。原分析未记录匹配代价矩阵，因此不展示虚构的关联分数。
- **LSTM**：第一轮/第一层/单元 0 在 50 个时间步的四门计算，每个门包含完整 51+256 个输入及权重；依次展示乘加、激活、记忆更新。10 层状态采样与全部 5 轮预测可查看，每轮解码器包含一个完整 256 维内积示例。
- **ST-GCN**：反标准化、固定参考配对标准化、DataBN 数值；10 个块均有完整代表元素计算：1×1 投影、3×17 个邻接项、全部输入通道×9 个时间点、残差/ReLU，以及池化。
- **分类头**：256 维池化向量、三组完整权重内积、Logits、稳定 Softmax 指数/分母与最终分数。

全链路均可浏览，详细运算采用明确选定的代表元素；并不保存每一层的全部激活或展开 YOLO 所有内部子算子。热力图显示真实采样位置与原始尺寸。动画前几项慢放，其余项仍完整计入；输入/权重、乘积、部分和与输出共用受控时间轴，暂停与倒拖可以重建同一状态。

接口：

- `GET /api/jobs/<id>/network?frame=<记录帧>&track_id=<ID>`：最多缓存 8 个响应，每个上限 5 MiB。
- `GET /api/jobs/<id>/frontend-network?frame=<源帧>`：最多缓存 3 个响应，每个上限 3 MiB。

记录重算与视频推理互斥，快速切换会取消旧请求并有限重试；网页任务启用有界实时采样，独立命令行默认不安装这些钩子。浏览器收到的是真实数值，计算动画与视频本身互不改写。

交互设计参考官方项目 [CNN Explainer](https://poloclub.github.io/cnn-explainer/)、[Transformer Explainer](https://poloclub.github.io/transformer-explainer/) 与 [LLM Visualization](https://bbycroft.net/llm)：全网概览、算子展开、单元级数值检查。实现基于本仓库模型，没有移植这些项目的代码或模型。

## 结果与模型口径

运行文件保存在 `artifacts/web/jobs/<任务ID>/`，每次任务使用独立目录。完整 ZIP 包含：

- `result.mp4`：带骨架、跟踪 ID 和预测类别的 H.264 视频；沿用原流程的无音轨输出。
- `predictions.jsonl`：逐帧结果与观测关键点。
- `metrics.json`：设备、环境、实际处理次数和耗时。
- `trace.json`：最多 60 个时间快照、每个最多三个行人的真实历史和未来姿态，供步骤回放使用。

模型默认使用 v1.0.0 配套权重与 `legacy_pair`。历史不足、姿态不足与断轨不会被填充成分类结果；类别“其他”对应 JAAD irrelevant。三类数值为模型分数，不是已验证的准确率。ST-GCN 使用模型中实际的 17 关节图定义；连线动画解释运算关系，热力图数值来自真实前向钩子，不能将图示亮度解读为模型对关节的重要性。

输入视频的原始帧率与分析吞吐分别记录。预览会限流以保持界面响应，最终视频仍按原输入帧序写出。上传默认最大 500 MB，超过时可先截取较短片段。

## 配置与开发

```sh
python run_web_demo.py --port 8765 --model-dir weights/final --max-upload-mb 500
```

服务只监听本机 `127.0.0.1`。`--data-dir` 可指定任务保存目录。前端开发可在 `web_demo/` 运行 `npm run dev`，Vite 的 `/api` 请求代理到本机 8765 端口。

缺少模型时，运行下载脚本；模型校验不一致时先保留现有文件，再检查配套模型包。缺少 ffmpeg 或视频无法解码时，界面会给出错误。服务重启后，已完成任务可继续读取；尚未完成的任务会标为中断。
