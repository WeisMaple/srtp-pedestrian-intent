# 本地网页演示

项目定位为**深度学习课程大作业**，题目为“基于人体骨架时序建模的行人过街意图预测”。网页是本地蓝图长廊：工作台选择视频，六步长廊沿一次真实前向展示视频帧、YOLO 骨架、ID 绑定、LSTM 预测、ST-GCN 与意图，结果页提供真实输出与下载。

全站只监听 `127.0.0.1`，不调用远程 API，不需要账号或字体 CDN。所有显示数值来自实时前向钩子或本地记录重算；未采集显示“未采集”，不补零、不编造。类别分数是模型输出，不是已验证的道路准确率。

## 首次准备

先按照仓库说明准备 Python 3.9、基础依赖、PyTorch 和现代 YOLO 环境。再安装网页依赖并构建前端：

```sh
python -m pip install -r requirements-web.txt
python download_final_models.py
cd web_demo
npm install
npm run build
cd ..
```

本机还需能执行 `ffmpeg`；它负责将结果转为浏览器可播放的 H.264 MP4。模型默认取自 `weights/final/`，服务启动时按发布清单校验全部文件。

## 启动与页面

```sh
python run_web_demo.py
```

打开 **http://127.0.0.1:8765**。已配置的 Mac 环境也可运行 `.venv/bin/python run_web_demo.py`。

### 工作台 `#/workbench`

- 拖入或选择 MP4 / MOV / AVI；显示文件名、时长、帧率、分辨率与首帧灯箱预览。
- 显示本地模型状态；主按钮“开始分析”，运行中显示处理帧、进度与“停止分析”。
- 分析开始后可直接进入长廊；关闭页面不会取消任务，重新打开会恢复最近任务或运行中的任务。
- 完成后出现“进入长廊”与“查看结果”，结果页提供标注 MP4、逐帧 JSONL 与完整 ZIP。
- 上传默认上限 500 MB。上传文件仅保存在本机 `artifacts/web/jobs/<任务ID>/`。

### 现场视频 `#/camera`

- 点击顶部“现场视频”，选择内置或 USB 摄像头，再点击“开启摄像头”。首次使用时允许浏览器访问摄像头；不申请麦克风权限。
- 主画面显示与骨架、跟踪 ID 和意图分数严格对应的识别帧，右上角保留连续实时预览。右侧列出当前行人和三类分数，本页不展示计算过程。
- 每个 ID 积累 50 次有效骨架后沿用原 LSTM→ST-GCN 输出意图，预热期间显示真实的 `n/50`。计数按已处理的有效观测，不按摄像头原始帧率。远景、遮挡或持续姿态不足可能无法达到 50 次。
- 沿用模型包配置的 PoseFilter：短暂缺失关节最多保持两次观测，随后失效；模型基于处理后的骨架判断有效性。无效骨架、较长断轨、超过两秒的采集间隔或分辨率变化会清空相关历史，避免沿用旧意图。
- 可随时切换摄像头、停止识别或隐藏骨架。停止、切换页面、页面进入后台或连接断开时释放摄像头、清空现场结果；回到页面后手动重新开启。
- 摄像头画面只在内存中处理，不录制、不生成任务文件。现场识别与视频分析、历史计算共用一个推理资源，正在进行其他推理时会给出提示。
- 浏览器以最长边 960 像素的 JPEG 发送画面，上一帧完成后才取下一帧，最多约 10 次/秒；实际帧率取决于机器与行人数，界面显示实测识别帧率和往返耗时。摄像头连续预览的帧率与识别帧率不同。
- 使用本机 `http://127.0.0.1:8765`；浏览器摄像头访问需要安全上下文（localhost 或 HTTPS）。权限被拒绝时，在地址栏站点权限中允许摄像头后重试。网页依赖中的 `websockets==15.0.1` 为此功能提供服务端连接支持。

### 长廊 `#/corridor`

六步沿同一个三维蓝图场景展开：

| 步 | 展位 | 显示的真实数据 |
| --- | --- | --- |
| ① | 视频帧 | 任务元数据；左侧上下文条显示源视频与当前所选行人 |
| ② | YOLO 骨架 | 实时 `tracks` 的检测框、17 关节、检测置信度；可展开模块卷积放大镜 |
| ③ | ID 绑定 | ByteTrack ID、姿态是否接受、历史有效观测 `n/50`、当前骨架 |
| ④ | LSTM 预测 | 实时 LSTM 轮次、未来骨架；首轮解码代表算式可检查 |
| ⑤ | ST-GCN | 当前骨架图、块选择器与空间/时间代表算式 |
| ⑥ | 意图 | 当前所选行人的三类概率柱与分类头代表算式 |

#### 第⑤步：骨架时空图与同页计算

第⑤步将空间邻域聚合和时间卷积同时展示。主图把同一行人的预测骨架沿时间排列，青色表示当前帧内的空间邻域，金色连接时间窗口中同一关节。下方两类数值与图上的骨架绑定同一个任务、来源帧、行人 ID 和卷积块。

- 顶部明确标注“实时采集”或“记录重算”，并显示实际来源链：50 次 YOLO 有效观测 → LSTM 预测 50 帧 → 归一化 / 特征变换 → ST-GCN。
- 使用无透视变形的二维矢量图，并列展示空间邻域局部放大与多帧骨架；中文关节名称的引线指向原坐标。支持 1× / 1.5× / 2× 放大、键盘选择、原图 x/y 坐标核对；实时新帧及等待数据不会重置缩放。默认隐藏第三通道预测分数 ≤0.2 的点及相关骨骼线，并从显示缩放范围中排除这些点；“显示原始低分点”可用空心点和虚线核对。模型输入和计算结果保持不变，该预测分数不是校准后的检测置信度。
- 空间边来自模型的实际邻接矩阵与有效权重；点击参与邻居或骨架关节，可联动检查空间乘加。点击时间位置或切换输入通道，可联动检查时间乘加。
- 两类代表计算始终可见，分别显示输入、权重、乘积、完整求和、实测输出与重建误差。全部参与项在各自计算面板内展开。
- 深层时间步结合前序层步长映射到预测序列的定位中心和时间感受野；骨架用于说明来源位置，深层输入数值是特征。空间、时间代表算式各自标出采样位置，二者之间经过 BN / ReLU。
- 边界位置显示空框与真实零填充，不复制骨架。当前帧未采集完整来源时显示等待，不借用其他帧或行人的算式。
- 新采集的详细记录保留来源任务与帧号，因此初次连接或重连时可以从同源快照恢复计算。旧版未标记来源的缓存不用于绑定当前骨架；已完成任务仍可通过记录重算查看。
- 1440×900 和 1920×1080 桌面视口下，骨架图、空间计算、时间计算与主要控制可同时显示；窄屏纵向排列，时间位置条可横向滚动。

#### 记录重算（已完成任务）

- 任务状态为 `completed` 时，步骤 ② 出现“记录重算”开关；它只读取源帧重算，不启动新的视频分析。
- 源帧与 YOLO 模块可独立选择；前端调用 `GET /api/jobs/<id>/yolo-conv?frame=<源帧>&module=<0-23>`，用 `normalizeCalculation` 展开完整参与项，并用同一个数值台显示实际输出、重建、部分和与误差。
- 记录行保留独立 Conv / BatchNorm / SiLU（`metadata.bn` 提供 γ、β、running mean/variance、ε），按 6 位小数序列化，与融合推理可能存在浮点舍入差异；界面始终标注“记录重算”并显示实际输出、重建与误差。
- 运行中、失败或取消的任务不提供该开关；`/api/jobs/<id>/network`、`/api/jobs/<id>/frontend-network` 仍是后端可用接口，但当前 UI 只接入 YOLO 单模块记录重算。

## 实时采集、覆盖与预算

实时展示通过生产推理的前向钩子采样，**不为动画额外执行一次模型**。YOLO 采集融合后模块输出；LSTM 采集五轮预测中的十层 h/c 状态、序列输出与未来骨架；ST-GCN 采集十块空间/时间/残差输出，以及池化、Logits 和本次分类分数。行为网络只在积累 50 次有效观测后出现实测输出。

- 每秒最多采集 4 个推理帧，每帧最多 3 人；浏览器最多每秒刷新 10 次数据。模型处理吞吐、采样率与屏幕渲染帧率相互独立。
- 每事件上限 128 KiB，每帧最多 192 事件 / 768 KiB；重连缓冲最多 1024 事件 / 8 MiB。只传真实采样切片与原尺寸、索引，不复制全层张量。
- `GET /api/jobs/<id>/live` 为 SSE：支持序号、重连、缺口快照、终态。任务结束后保存 `live.json`，重开页面可检查最后采样帧；它不是完整逐帧计算录像，也不含在结果 ZIP 中。
- 页面区分采集帧、已收到层数、当前帧耗时和接收状态。层耗时为主机墙钟区间，包含嵌套观察开销，不是 GPU 核函数耗时。预览显示最近完成的画面，可能稍落后于正在计算的帧。
- 无 WebGL 或渲染上下文丢失时，长廊显示数值回退提示，底部数值台仍可使用；减少动画设置会关闭镜头飞行与装饰流光。

详细采集预算与覆盖（来自数据基础计划）：

- **奇偶详细帧配对**：每个 ST-GCN 块占用一对详细帧。奇数详细帧采集该块的空间/中段行，并轮转采集 4 个 YOLO 模块；偶数详细帧采集同一块的空间/中段/边界行，不采集 YOLO 模块，YOLO 推理本身仍正常执行。
- **YOLO 覆盖**：24 个顶层模块按 4 个一组轮转，正常 6 个奇数详细帧（12 个详细帧）完成一轮。
- **ST-GCN 覆盖**：10 个块每 2 个详细帧前进一块，20 个详细帧完成一轮。边界样例在 256 通道深块上每个详细帧只取 1 个轮转行人，三个 20 帧周期（1 fps 下约 60 秒）覆盖全部行人。
- **预算**：单事件上限 128 KiB；详细算式单帧上限 512 KiB；单帧总事件上限 768 KiB。达到预算时只在覆盖进度中显示已调度/已接收的部分，不截断求和，也不补造数值。
- **重配对回退**：当 2304 项时间卷积块与含两个 2304 项代表卷积的 YOLO 组相遇时，四模块加三人的整帧连同随后分类行会超过 768 KiB（成功发出 779,121–785,608 B 后仍丢弃 2–3 条分类行；512 KiB 详细上限本身未被触及）。此时奇数详细帧只采集该组的前 2 个模块；其余模块在较轻的配对中重新调度，`detail.coverage` 只报告本帧实际调度的模块，页面显示“等待详细采集”。实测回退后四个重配对帧为 706,503–725,942 B，3/3 分类行保留，无预算丢弃；最大单事件 83,313 B，单帧详细字节 349,879 B。
- **实测与门槛**：2026-11-04 在本机 macOS arm64、Python 3.9.25、PyTorch 2.2.2、Ultralytics 8.4.190、CPU 上，使用 `artifacts/demo/demo_input.mp4`（75 帧、1280×720、30 fps）和 `weights/final`，运行 `--repeat 3`。关闭/启用详细采集的 `processing_seconds` 中位数分别为 10.351 / 10.234 秒（单次范围 10.026–10.693 / 10.071–11.098 秒），差值为 −1.13%，在运行波动范围内，远低于 15% 门槛；因此保留 1 fps / 4 模块 / 1 块，不启用 0.5 fps + 2 模块的 15% 回退。本轮单事件最大 68,167 B；详细事件总量随运行在约 1.0 MB 波动（单帧仍受 512 KiB 限制），无超限、无预算丢弃。75 帧约 10 秒处理完，因此最多记录 10 个详细帧，3 次运行合计覆盖 20/24 个 YOLO 模块和 0–4 号块；其余模块/块按覆盖进度等待下一轮。完整实测记录见 `docs/superpowers/reports/2026-11-04-live-detail-benchmark.md`。

## 结果与模型口径

运行文件保存在 `artifacts/web/jobs/<任务ID>/`，每次任务使用独立目录。完整 ZIP 包含：

- `result.mp4`：带骨架、跟踪 ID 和预测类别的 H.264 视频；沿用原流程的无音轨输出。
- `predictions.jsonl`：逐帧结果与观测关键点。
- `metrics.json`：设备、环境、实际处理次数和耗时。
- `trace.json`：最多 60 个时间快照、每个最多三个行人的真实历史和未来姿态。

模型默认使用 v1.0.0 配套权重与 `legacy_pair`。历史不足、姿态不足与断轨不会被填充成分类结果；类别“其他”对应 JAAD irrelevant。三类数值为模型分数，不是已验证的准确率。ST-GCN 使用模型中实际的 17 关节图定义；图示亮度与颜色表示当前计算参与关系，不能解读为模型对关节的重要性。ByteTrack 匹配代价没有记录，界面不显示虚构的关联分数。

输入视频的原始帧率与分析吞吐分别记录。预览会限流以保持界面响应，最终视频仍按原输入帧序写出。

## 统一控件

工作台、运算过程、现场视频与结果页共用 `web_demo/src/components/ui/` 控件层：按钮、页面内下拉菜单、滑块、数字步进、复选框、进度条、折叠明细、文件选择入口及视频播放器。样式集中在 `styles/controls.css`，包含焦点、禁用状态和滚动条。

下拉菜单支持方向键、Home/End、Enter/Tab 确认、Escape 取消；长菜单独立滚动，靠近屏幕底部时向上展开。重复确认同一个值不触发变化，因此不会重启摄像头。播放器提供播放/暂停、拖动进度、静音、倍速和全屏；聚焦播放器区域时可用空格播放、左右键跳转五秒。计算回看仍使用自己的逐帧同步控件。

## 配置与开发

```sh
python run_web_demo.py --port 8765 --model-dir weights/final --max-upload-mb 500
```

服务只监听本机 `127.0.0.1`。`--data-dir` 可指定任务保存目录。前端开发可在 `web_demo/` 运行 `npm run dev`，Vite 的 `/api` 请求代理到本机 8765 端口。

缺少模型时，运行下载脚本；模型校验不一致时先保留现有文件，再检查配套模型包。缺少 ffmpeg 或视频无法解码时，界面会给出错误。服务重启后，已完成任务可继续读取；尚未完成的任务会标为中断。
