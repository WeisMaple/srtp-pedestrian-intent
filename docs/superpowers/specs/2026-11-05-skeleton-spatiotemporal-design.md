# 骨架时空卷积同页展示设计

## 用户目标

时空卷积的计算与展示依赖前面提取的同一行人骨架，清楚体现空间、时间两个维度，尽可能在同一页面完整展示。

用户已选择“统一骨架时空图＋联动计算”：多帧骨架沿时间轴排列，帧内连线表示空间邻域，同一关节跨帧连接表示时间窗口，旁边同步展示两类计算。

## 方案比较

- **统一骨架时空图＋联动计算（用户选择）**：时间与空间共享同一组骨架和选择状态，最容易追溯输入与计算的联系；需要控制骨架和连线密度。
- **空间、时间左右分屏**：单独讲解较清楚，但会重复展示骨架，需要来回对照两幅图。

## 页面与交互

改造现有运算过程第⑤步，沿用 React、Three.js、现有蓝图配色和统一控件。

1. **顶部来源条**：源帧、行人 ID、50 次观测 → LSTM 预测骨架 → 当前 ST-GCN 块。显示当前数据属于实时采集还是记录重算。
2. **中央骨架时空图**：将同一行人的真实预测骨架按时间排列。重点显示当前时间窗口，保留全序列定位条。用不同颜色同时标出帧内目标关节及其邻域、跨时间的同一关节。图例明确空间连线、时间连线、当前目标、零填充。
3. **旁侧联动计算**：空间聚合与时间卷积同时可见，各显示当前输入、权重、乘积、求和及独立实测输出。选中实际参与项时，高亮图上的对应关节或时间位置；缺少采集的部分显示等待。
4. **底部紧凑控制**：卷积块、时间窗口、输入通道与播放控制。详细参与项在本页展开，默认不占用大块空间。不再以“计算类型”下拉框隐藏另一维度。

桌面端以 1440×900 和 1920×1080 为检查尺寸，尽量一屏覆盖来源、主图、两类计算及主要控件。较窄屏幕改为纵向排列，允许页面滚动，保留两维内容。可旋转、缩放、重置视角；减少动画偏好关闭自动镜头运动。

## 数据正确性

- 延续当前实际链路：YOLO 骨架 → 同一 ID 的 50 次有效观测 → LSTM 未来 50 帧 → 归一化及 ST-GCN。观测骨架与预测骨架明确标注。
- 使用已有实时事件与完成任务的 `/network` 重算结果；实时展示不额外执行模型推理。
- 图和数值必须绑定同一任务、来源帧、行人和卷积块。不能把缓存中的旧帧计算挂到新的骨架上；切换对象或加载期间清除旧内容。
- 空间关系使用模型的实际邻接矩阵和有效权重，不能以绘图用 COCO 连线代替模型图连接。
- 第一个块的坐标输入经过归一化，后续块输入是特征。深层时间位置结合实际步长标明对应的输入序列位置/感受野；展示用骨架提供来源定位，不宣称某个深层特征等于单帧原始坐标。
- 空间代表算式与时间代表算式若采样位置不同，明确标出各自位置。只在位置、通道与中间变换一致时表示直接数值传递，保留 BN / ReLU 的连接说明。
- 边界零填充独立表示，不复制骨架填补空位。预测帧序号、有效观测序号、视频帧号和层内时间索引分别标注。
- 保留实际权重、完整求和与重建误差；代表性输出注明范围，不伪装成整层全部运算。

## 改动范围与验证

重点涉及第⑤步组件、骨架时空场景、实时/重算数据适配和布局样式；必要时补齐展示元数据。保持已验证的 50 次观测及 LSTM→ST-GCN 推理行为。

验证同源骨架绑定、空间/时间索引、深层步长、零填充、缺失数据、切换行人/帧和计算重建。运行相关前端、后端回归及生产构建，再用已有真实视频与最终权重检查页面、记录重算和输出。若运行完整后端回归，明确报告因历史 Windows 权重缺失而跳过的五项检查。
